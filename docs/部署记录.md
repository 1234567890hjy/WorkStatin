## 二、部署做了什么

### 1. 架构改动：Worker 直接托管前端

原设计是「Pages 托管前端 + Worker 托管 API」，但两者不同域，前端相对路径 `/api` 会 404。

改成 Worker 托管静态资源（`wrangler.toml` 的 `[assets]`）：

```toml
[assets]
directory = "../web/dist"
binding = "ASSETS"
not_found_handling = "single-page-application"
run_worker_first = ["/api/*"]
```

好处：

- **一次部署**，不用单独发 Pages
- **天然同源**，`/api` 直接工作，不需要 `_redirects` 或自定义域
- SPA 路由回退到 `index.html`，`/share` 能正常命中前端
- 成本仍是 0

### 2. 创建 D1 并建表

```bash
npx wrangler@4 d1 create workstation-db          # → ea9195ab-...
npx wrangler@4 d1 migrations apply workstation-db --remote   # 28 条命令
```

### 3. 部署

```bash
cd apps/web && npx vite build                     # 44 模块 → 199KB (gzip 62KB)
cd apps/worker && npx wrangler@4 deploy           # 上传 6 个静态资源 + Worker
```

### 4. 注册 workers.dev 子域名

账号原本没有子域名，用 Cloudflare API 创建：

```bash
PUT /accounts/{account_id}/workers/subdomain
{"subdomain": "workstation-me"}
```

## 四、本机访问不了的真正原因

### 现象

```
$ Test-NetConnection workstation-me.workstation-me.workers.dev -Port 443
TCP443: False

$ Resolve-DnsName workstation-me.workstation-me.workers.dev -Type A
IPAddress: 173.252.88.133     ← 这是 Facebook 的 IP
```

### 诊断

| 域名 | 结果 |
|---|---|
| `cloudflare.com` | ✅ 200 |
| `workers.cloudflare.com` | ✅ 200 |
| `api.cloudflare.com` | ✅ 可达（API 调用全部成功） |
| `*.workers.dev` | ❌ DNS 解析到 `173.252.88.133`（Facebook IP），TCP 443 不通 |

对照组：`www.google.com` 在本机解析到 `127.0.0.1`。

**结论**：这台机器的网络环境对 `*.workers.dev` 做了 DNS 污染，不是部署问题。
`workers.dev` 域名在中国大陆长期不稳定，这是已知情况。

## 五、你怎么访问

### 方案 A：先确认是否只有本机不行（最快）

**用手机 4G/5G 流量**（不连 WiFi）打开：

```
https://workstation-me.workstation-me.workers.dev
```

- 能打开 → 说明是家里网络的 DNS 问题，换个 DNS 即可（见方案 B）
- 打不开 → 说明运营商层面也干扰，需要方案 C

### 方案 B：换 DNS（如果只是本机 DNS 污染）

Windows 设置 → 网络 → 更改适配器选项 → WLAN → 属性 → IPv4 →
使用下面的 DNS 服务器：

```
首选：1.1.1.1
备用：8.8.8.8
```

然后 `ipconfig /flushdns`，再试。

> 注意：如果污染发生在运营商层（不只是本机 DNS），换 DNS 也没用。

### 方案 C：绑定自定义域名（最稳，但要你有域名）

`workers.dev` 不稳定，**自己的域名走 Cloudflare 代理则稳定得多**。

前提：你有一个域名，且已托管到 Cloudflare（Nameserver 指向 CF）。

步骤：

1. Cloudflare 控制台 → Workers & Pages → `workstation-me` → 设置 → 触发器 → 添加自定义域
2. 填 `ws.你的域名.com`
3. 自动创建 DNS 记录并签发证书（约 1 分钟）

之后用 `https://ws.你的域名.com` 访问。

**这个方案还顺带解决了另一个问题**：自定义域下 HTTPS 稳定，
Service Worker 能可靠注册，**分享导入才真正可用**。

如果你有域名，告诉我，我帮你配。

### 方案 D：临时用隧道（不想买域名时）

在能访问 Cloudflare 的机器上跑 Cloudflare Tunnel，
把本地 `wrangler dev` 暴露到公网。但要求那台机器一直开着，不适合长期用。

## 六、部署后你要做的第一件事

打开线上地址，会看到「首次使用，创建你的账号」。

**务必设一个强口令**（至少 8 位）。这是公网暴露的单用户系统，
虽然有登录限流（每 IP 每小时 10 次失败），但口令强度是第一道防线。

注册后：

1. 手机 Chrome 打开 → 菜单 → 「添加到主屏幕」
2. 从主屏启动（全屏，无地址栏）
3. **测试分享导入**：在短信里长按一条消费短信 → 分享 → 找「工作台」

如果分享面板里没有本应用，说明 Service Worker 没注册成功 ——
检查浏览器控制台 Application → Service Workers。
