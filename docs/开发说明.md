# 开发说明

## 环境要求

- Node.js ≥ 20（当前用 24.14.0 验证）
- Python ≥ 3.8（仅用于迁移脚本校验，可选）
- 无需 Docker、无需 PostgreSQL、无需 Redis

## 目录结构

```
apps/
  worker/            Cloudflare Worker（Hono + D1）
    src/
      domain/        纯逻辑：金额、分享解析、日期、认证、任务校验、日常校验、账户分类校验
      routes/        HTTP 路由
      db.ts          汇总表维护
      index.ts       入口
    migrations/      D1 迁移脚本
    test/            测试
  web/               PWA（React + Vite + Tailwind）
    src/
      pages/         页面
      components/    可复用组件（天气卡、分类占比图）
      api.ts         API 客户端
      App.tsx        路由与底部 tab
docs/                方案与设计文档
tools/               辅助脚本
```

## 常用命令

```bash
# 安装依赖（沙箱内必须加 --ignore-scripts）
npm install --ignore-scripts

# 类型检查
npx tsc -p tsconfig.worker.json      # Worker
npx tsc -p tsconfig.test.json        # 测试代码
cd apps/web && npx tsc -p tsconfig.json   # 前端

# 测试（沙箱内 vitest / vite build 都要 spawn esbuild，起不来，用自包含 runner）
node --experimental-strip-types apps/worker/test/run.ts      # 单元：73 项
node --experimental-strip-types apps/worker/test/smoke.ts    # 冒烟：112 项
python tools/check-migrations.py                 # 迁移脚本校验

# 前端构建（需要 danger-full-access）
cd apps/web && npx vite build

# 本地开发（需要能 spawn 子进程的环境）
cd apps/worker && npx wrangler dev --local
cd apps/web && npx vite
```

## 首次部署

```bash
# 1. 创建 D1 数据库
npx wrangler d1 create workstation-db
# 把返回的 database_id 填进 apps/worker/wrangler.toml

# 2. 执行迁移
cd apps/worker
npx wrangler d1 migrations apply workstation-db --remote

# 3. 部署 Worker
npx wrangler deploy

# 4. 部署前端到 Pages（构建产物在 apps/web/dist）
npx wrangler pages deploy apps/web/dist --project-name workstation-me
```

部署后首次打开页面会要求**创建账号**（仅一次），之后走登录。

## 关键设计决策

### 金额一律用「分」的整数

`amount_cents: number`，绝不用浮点。`0.29 * 100 = 28.999...` 这类问题在记账里是致命的。
解析用户输入时走字符串拆分（见 `domain/money.ts`），不走 `parseFloat`。

### 月度汇总用「写时重算」而不是触发器

D1 没有物化视图。每次写事务后，对**受影响的月份**整体重算 `monthly_summary`
（`db.ts: rebuildMonth`）。单人单月几百行，重算是毫秒级，换来「永远不会算错」。

跨月修改时两个月份都会重算（`routes/txn.ts` 的 PUT 分支）。

### share_target 只预填、不自动落库

Android 分享过来的文本不可信，`/api/share/parse` 只返回草稿，
用户必须在确认页核对后点「确认记账」。解析失败一律落回手填。

### 认证用 PBKDF2 而不是 argon2

Workers 没有原生 argon2，纯 JS 实现既慢又容易撞 CPU 限额。
PBKDF2-SHA256 + 10 万轮 + 16 字节随机盐，配合登录限流，对单人自用足够。

会话 token 入库前先 SHA-256，数据库泄露也无法直接冒用。

### 视频学习不做下载、不做 ASR

`yt-dlp + ffmpeg + Whisper + GPU` 塞进小机器是三个烂零件：转写慢、解析随时失效。
所以**转写外包**给人（通义听悟等），系统只做「抓元数据 → 存转写 → LLM 摘要 → 归档检索」。

平台识别必须带域名边界：`evil-bilibili.com` 不能被认成 B 站
（`routes/video.ts: detectPlatform` 用 `host === d || host.endsWith('.' + d)`）。

### LLM 同步调用，不需要队列

Workers 的 CPU 计时**不含等待网络的时间**，等 30 秒也不烧 CPU。
所以摘要是普通同步 HTTP 调用，用 `AbortController` 兜 90 秒超时即可。
v1 方案里的 BullMQ / Redis / APScheduler 全部是凭空造出来的复杂度。

### 天气是卡片，不是模块

前端 30 分钟缓存 + Worker 侧 Cache API 双层兜底。
拿不到就显示「—」，**绝不能挡住主流程** —— 天气是锦上添花。

## 沙箱环境注意事项

本仓库在受限沙箱里开发，遇到以下限制及对策：

| 限制 | 表现 | 对策 |
|---|---|---|
| 禁止 spawn 子进程 | `npm install` 的 postinstall 失败 | 加 `--ignore-scripts` |
| 禁止 spawn 子进程 | esbuild 起不来 → vitest/vite build 无法运行 | 用 `test/run.ts` 自包含 runner + `tsc --noEmit` 验证 |
| npm 缓存目录在工作区外 | `EPERM ... npm-cache` | 项目内 `.npmrc` 指定 `cache` |
| `node --test` 需要子进程 | 报 `spawn EPERM` | 用 `test/run.ts` 自包含 runner |

## 测试策略

三层，各有分工：

1. **纯逻辑单测**（`test/run.ts`，自包含 runner，73 项）—— 金额、分享解析、日期、
   任务校验、日常校验、账户分类校验、周期计算、连续打卡天数。
   在 `danger-full-access` 下也可用 `npx vitest run` 跑同目录的 `*.test.ts`。
2. **接口冒烟**（`test/smoke.ts`，112 项）—— 用内存版 D1 替身跑通
   「初始化→改密→记账→汇总→运动→视频→任务→日常→账户分类→搜索→Dashboard」，
   验证路由挂载、鉴权、校验、汇总重算的真实控制流。
3. **迁移校验**（`tools/check-migrations.py`）—— 真实 SQLite 执行迁移，
   验证表结构、种子数据、CHECK 约束、汇总 SQL。

> 单元测试的**新增逻辑必须先抽到 `src/domain/`**：`routes/*.ts` import 了 Hono，
> 直接单测会把整个 Worker 拉起来。`domain/task.ts`、`domain/routine.ts`、
> `domain/meta.ts` 就是这么拆出来的。
>
> **改 FakeD1 时注意**：`seq` 计数器必须从种子数据的最大 id 起（category 种子到 id 10），
> 否则新增记录的 id 会与种子冲突，`SELECT ... WHERE id = ?` 返回错行。

## 已知限制

- `wrangler dev` 本地预览未验证
- 真实 D1 上的 SQL 行为未经实测，仅通过 SQLite 兼容性验证
- 视频模块只抓 B 站元数据；抖音等平台需手填标题
- 天气依赖 Open-Meteo 公网可达；不可用时卡片降级为「—」
- 无两步验证（`user.totp_secret` 字段已预留）
- 备份恢复演练、预算告警、天气×运动相关性尚未实现（P2）
- 沙箱内无法 vite build / vitest（esbuild 需 spawn 子进程）；已用 `tsc --noEmit` 等价验证
