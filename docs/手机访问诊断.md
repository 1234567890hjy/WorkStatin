### 矛盾点

**浏览器能打开，但所有命令行工具失败。**

可能的解释（按概率排序）：

1. **浏览器使用了不同的网络路径** —— 比如系统级代理、浏览器内置安全 DNS（DoH）、或某个扩展
2. **浏览器缓存了之前的成功结果** —— 但 `/api/health` 是新请求，不太可能
3. **TLS 指纹差异** —— 浏览器（BoringSSL）与命令行（Schannel/OpenSSL）的 ClientHello 不同，中间设备只针对某些指纹放行
4. **`eu.cc` 后缀被间歇性阻断** —— 时好时坏

**结论：阻断发生在网络中间层，不在服务端。**

## 三、如果手机确实访问不了：四个解决方案

### 方案 A：换一个没被针对的域名（最推荐）

`eu.cc` 是免费域名，这类后缀在国内被针对性干扰是常态。

**你账号下还有 2 个 `eu.cc` 域名，同样后缀，大概率一样不行。**

建议注册一个正经后缀的域名：

| 后缀 | 年费 | 说明 |
|---|---|---|
| `.top` | ¥10~20 | 最便宜，够用 |
| `.xyz` | ¥10~30 | 国际通用 |
| `.icu` | ¥8~15 | 便宜 |
| `.com` | ¥60~80 | 最稳 |

买完把 NS 指到 Cloudflare（`johnny.ns.cloudflare.com` / `tegan.ns.cloudflare.com`），
告诉我，我 5 分钟配好自定义域。

**这是唯一能彻底解决的路。**

### 方案 B：Cloudflare Tunnel 走国内中转（0 成本，需一台常开设备）

如果你有 NAS、软路由、或常开的电脑：

1. 在那台机器上跑 `npx wrangler dev`（本地服务）
2. 用 `cloudflared tunnel` 把本地端口暴露到公网
3. Tunnel 给你一个域名，可以绑到 Cloudflare

**但 Tunnel 默认也用 Cloudflare 的 IP，可能同样被阻断。**
除非你绑的是国内能访问的域名。

### 方案 C：改用国内云服务商（成本 ¥0~10/月）

把后端换成国内能访问的：

| 服务 | 免费额度 | 说明 |
|---|---|---|
| 阿里云函数计算 | 有免费额度 | 需要改代码适配 |
| 腾讯云 CloudBase | 有免费额度 | 支持 Node |
| Vercel（国内不稳） | 免费 | 不推荐 |

**代价**：需要重写部署适配层，约 1~2 天工作量。

### 方案 D：局域网 + 内网穿透（0 成本，体验受限）

- 家里电脑跑服务，手机连同一 WiFi 访问局域网 IP
- 出门用内网穿透（frp / natapp）访问
- **但内网穿透服务商通常也限速、收费**
