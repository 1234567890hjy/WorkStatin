## 二、Chrome 失败的原因

Chrome 有三个国内 OEM 浏览器默认关闭的特性，可能触发干扰：

| 特性 | 说明 |
|---|---|
| **安全 DNS（DoH）** | Chrome 默认开启，可能解析到被污染的 IP |
| **QUIC / HTTP3** | 走 UDP 443，可能被干扰且不回退到 TCP |
| **ECH**（加密 Client Hello） | Chrome 124+ 默认尝试，可能触发阻断 |

Vivo 浏览器是 Chromium 精简分支，这些默认关闭，所以正常。

### 顺带解释：为什么本机命令行也失败

开发机上的 `curl` / PowerShell / Node 全部在 TLS 握手被 RST，但同一台机器的浏览器能打开。

这和手机上的现象**同源**：某些客户端的 TLS 指纹或协议特性被针对性干扰。
所以命令行测试结果**不能作为「域名被封」的依据** —— 浏览器端实测才可信。

---

## 三、Chrome 修复步骤（按顺序试）

### 1. 关闭安全 DNS（最可能有效）

```
Chrome 设置 → 隐私和安全 → 安全 → 使用安全 DNS → 关闭
```

### 2. 禁用 QUIC

地址栏输入 `chrome://flags/#enable-quic` → 设为 **Disabled** → 重启 Chrome

### 3. 禁用 ECH

地址栏输入 `chrome://flags/#encrypted-client-hello` → 设为 **Disabled** → 重启 Chrome

### 4. 清除缓存后重试

```
Chrome 设置 → 隐私和安全 → 清除浏览数据 → 缓存的图片和文件
```
