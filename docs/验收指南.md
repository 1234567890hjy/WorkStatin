## 一、先回答「有 App 端吗」

**没有原生 App，也不需要装 APK。**

这是一个 **PWA（渐进式 Web 应用）**：

| | 原生 App | 本项目 PWA |
|---|---|---|
| 安装 | 应用商店 / APK | 浏览器打开 → 「添加到主屏幕」 |
| 桌面图标 | 有 | 有（装到主屏后和 App 一样） |
| 全屏运行 | 是 | 是（`display: standalone`） |
| 分享导入 | 是 | **是**（靠 `share_target` + Service Worker） |
| 成本 | 需打包、签名、上架 | 零 |

**为什么不做原生 App**：单人自用，一套代码同时满足手机和 PC；原生 App 要维护 Android/iOS 两套壳，
且分享导入用 PWA 完全能实现。方案 v2 里已明确这个取舍。

### 但有一个前提

`share_target`（从短信分享导入）**只在 HTTPS 下生效**，`localhost` 例外。
所以：

- **电脑上 `http://localhost:5173`** → 可以完整验收所有功能（含分享模拟）
- **手机上 `http://192.168.x.x:5173`** → 界面、记账、运动、视频都能用，
  **但「分享导入」不可用**（Chrome 要求安全上下文）

要用真正的分享导入，必须先部署到公网 HTTPS（见第五节）。

## 二、现在就能做的验收（本地，5 分钟）

### 启动

两个服务当前已经在跑。如果重启过，按下面来：

```bash
# 终端 1：后端
cd "D:\Workstatin Me\apps\worker"
$env:TMP="D:\Workstatin Me\.tmp"; $env:TEMP="D:\Workstatin Me\.tmp"
npx wrangler@4 dev --local --port 8787 --persist-to "D:\Workstatin Me\apps\worker\.wrangler-state"

# 终端 2：前端
cd "D:\Workstatin Me\apps\web"
npx vite --port 5173 --host
```

> 注意必须用 `wrangler@4`。项目里装的 3.114 在这台机器上会 `std::terminate` 崩溃。
> 还必须重定向 `TMP`，否则 workerd 在系统目录建 `miniflare-email-store` 被拒绝访问。

### 打开

浏览器访问 **http://localhost:5173**

已有一个测试账号（我在验证时创建的）：

```
用户名：owner
口令：test12345
```

**建议你自己重新建一个**：删掉 `apps/worker/.wrangler-state` 目录后重启，页面会重新要求「创建账号」。

## 五、要真正用起来，必须部署（这一步需要你做）

代码已就绪，但**部署我无法替你完成**，因为需要你的 Cloudflare 账号。

```bash
cd "D:\Workstatin Me"

# 1. 登录 Cloudflare（会打开浏览器）
npx wrangler@4 login

# 2. 创建 D1 数据库
cd apps/worker
npx wrangler@4 d1 create workstation-db
# 把输出的 database_id 填进 wrangler.toml 的 database_id（替换 REPLACE_WITH_YOUR_D1_ID）

# 3. 建表
npx wrangler@4 d1 migrations apply workstation-db --remote

# 4. 配 LLM（可选）
npx wrangler@4 secret put DEEPSEEK_API_KEY

# 5. 部署后端
npx wrangler@4 deploy

# 6. 构建并部署前端
cd ../web && npx vite build
npx wrangler@4 pages deploy dist --project-name workstation-me
```

部署后拿到 `https://workstation-me.pages.dev` 这样的域名，**那时分享导入才真正可用**。

### 部署后要改一处

`apps/web/src/api.ts` 里 API 走的是相对路径 `/api`，这要求前端和 Worker 同域。
Cloudflare Pages 和 Worker 默认不同域，需要二选一：

- **方案 A（推荐）**：在 Pages 配 `_redirects` 把 `/api/*` 代理到 Worker
- **方案 B**：给 Worker 配自定义域，让 `api.你的域名` 和页面同主域

这一步等你真要部署时告诉我，我来改。

## 七、已知限制（诚实清单）

| 限制 | 影响 |
|---|---|
| 未部署公网 | 分享导入在手机上不可用；换网络后数据不通 |
| 无原生 App | 无法用系统级通知、后台定位、离线写入 |
| 未配 LLM 密钥 | AI 摘要不可用，需手写 |
| 视频只抓 B 站元数据 | 抖音等需手填标题 |
| 真实 D1 未实测 | SQL 仅在 SQLite 兼容层验证过 |
| 天气依赖 Open-Meteo | 国内访问可能不稳定，失败时降级为「—」 |
| 无两步验证 | `user.totp_secret` 字段已预留，未实现 |
| 全局搜索是 LIKE 而非 FTS | 单人数据量下够用；上万条后需考虑 FTS5 |
| 沙箱内无法 vite build | esbuild 需 spawn 子进程；已用 `tsc --noEmit` 等价验证 |
